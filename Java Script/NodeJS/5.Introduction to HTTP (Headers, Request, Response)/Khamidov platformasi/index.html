  • HTTP (Hypertext Transfer Protocol)

      HTTP (Hypertext Transfer Protocol)

      HTTP — bu veb-saytlar va ilovalar internetda qanday ishlashini belgilab beruvchi asosiy protokoldir. U klient (masalan, sizning brauzeringiz) va server (veb-sayt joylashgan kompyuter) oʻrtasidagi aloqani boshqaradi. Bu aloqa har doim ikki tomonlama boʻladi:

      • Klient soʻrov yuboradi (Request).
      • Server javob qaytaradi (Response).

      1. HTTP Request (Soʻrov)

      Bu, sizning brauzeringiz maʼlumot olish yoki maʼlumot yuborish uchun serverga yuboradigan xabardir. U 3 ta asosiy qismdan iborat:

      a) Soʻrov qatori (Request Line)

      Soʻrov qatori soʻrovning eng birinchi qismi boʻlib, u 3 ta asosiy elementni oʻz ichiga oladi:

      • Method (Metod): Serverdan nima qilishni soʻrayotganingizni belgilaydi. Eng koʻp ishlatiladiganlari:
        • GET: Serverdan maʼlumot olish uchun (masalan, sahifani ochish).
        • POST: Serverga maʼlumot yuborish uchun (masalan, roʻyxatdan oʻtish yoki izoh qoldirish).
        • PUT: Serverdagi mavjud maʼlumotni yangilash uchun.
        • DELETE: Serverdagi maʼlumotni oʻchirish uchun.
      • Path (Yoʻnalish): Serverdagi qaysi resursga murojaat qilayotganingizni koʻrsatadi (masalan, /about.html yoki /products/123).
      • HTTP Version (HTTP versiyasi): Aloqa qaysi versiya boʻyicha olib borilishini belgilaydi (odatda HTTP/1.1 yoki HTTP/2).

      Misol: Siz google.com saytiga kirmoqchi boʻlganingizda, brauzeringiz quyidagicha soʻrov qatori yuboradi:

      GET / HTTP/1.1

      b) Headers (Sarlavhalar)

      Bu soʻrov haqida qoʻshimcha maʼlumotlarni oʻz ichiga oladi va kalit-qiymat (key-value) juftliklari koʻrinishida boʻladi:

      • Host: www.google.com — Soʻrov qaysi serverga yuborilayotganini koʻrsatadi.
      • User-Agent: Mozilla/5.0 ... — Soʻrov yuborayotgan brauzer yoki ilova haqida maʼlumot beradi.
      • Accept-Language: uz-UZ — Qaysi tilda javob qaytarilishini xohlayotganingizni koʻrsatadi.
      • Cookie: sessionid=... — Avvalgi seanslardan saqlangan cookie'larni yuboradi.

      Misol:

      GET / HTTP/1.1
            Host: www.google.com
            User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
            Accept-Language: uz-UZ,en-US;q=0.7,en;q=0.3

      2. HTTP Response (Javob)

      Bu, server klientning soʻroviga javoban yuboradigan xabardir. U ham soʻrov kabi 3 ta asosiy qismdan iborat:

      a) Holat qatori (Status Line)

      Holat qatori javobning boshlanishi boʻlib, u 3 ta elementni oʻz ichiga oladi:

      • HTTP Version (HTTP versiyasi): Server ishlatayotgan HTTP versiyasi.
      • Status Code (Holat kodi): Soʻrov natijasi haqida maʼlumot beruvchi uch xonali raqam. Eng koʻp ishlatiladiganlari:
        • 200 OK: Soʻrov muvaffaqiyatli bajarildi.
        • 404 Not Found: Soʻralgan resurs topilmadi.
        • 500 Internal Server Error: Serverda kutilmagan xatolik yuz berdi.
        • 301 Moved Permanently: Soʻralgan sahifa boshqa manzilga koʻchirilgan.
      • Status Message (Holat xabari): Holat kodi haqida qisqacha matnli tushuntirish.

      Misol:

      HTTP/1.1 200 OK

      b) Headers (Sarlavhalar)

      Bular javob haqida qoʻshimcha maʼlumotlar boʻlib, kalit-qiymat (key-value) juftliklari koʻrinishida boʻladi:

      • Content-Type: text/html — Javob tanasida qanday turdagi maʼlumot borligini koʻrsatadi.
      • Content-Length: 1234 — Javob tanasining hajmi.
      • Server: Apache — Javob bergan server dasturi haqida maʼlumot.
      • Set-Cookie: sessionid=... — Brauzerda saqlanishi kerak boʻlgan cookie'larni yuboradi.

      Misol:

      HTTP/1.1 200 OK
            Content-Type: text/html; charset=UTF-8
            Content-Length: 1564
            Date: Tue, 16 Sep 2025 07:00:00 GMT
            Server: Apache

      c) Body (Tana)

      Bu soʻrovga javob sifatida qaytariladigan asosiy maʼlumot. Agar soʻrov muvaffaqiyatli boʻlsa, bu yerda soʻralgan HTML sahifasi, JSON maʼlumotlari, rasm yoki boshqa fayl boʻladi.

      Misol:

      <!DOCTYPE html>
            <html>
            <head>
            <title>Google</title>
            </head>
            <body>
            <h1>Qidiruv sahifasi</h1>
            ...
            </body>
            </html>

      Tushunish uchun sodda misol: Restoran misoli

      HTTPning ishlashini tushunish uchun oddiy bir misolni koʻrib chiqaylik. Tasavvur qiling, siz restoranda ovqat zakaz qilmoqchisiz:

      • Siz — Klient.
      • Ofitsiant — HTTP.
      • Oshxona — Server.

      1. Sizning soʻrovingiz (Request)

      Siz (Klient) menyuni koʻrib, ofitsiantga zakaz berasiz (Request). Bu soʻrov quyidagi qismlardan iborat boʻladi:

      • Soʻrov qatori: "Iltimos, lagʻmon olib keling." (metod: GET, resurs: lagʻmon)
      • Sarlavhalar: "Men stolda 3-oʻrinda oʻtiribman." (oʻzingiz haqingizda qoʻshimcha maʼlumot).
      • Tana: Bu yerda hech narsa boʻlmaydi, chunki siz shunchaki maʼlumot soʻrayapsiz.

      2. Serverning javobi (Response)

      Ofitsiant soʻrovni oshxonaga yetkazadi. Oshxona uni tayyorlaydi. Keyin ofitsiant sizga ovqatni olib keladi (Response). Javob quyidagilarni oʻz ichiga oladi:

      • Holat qatori: "Zakazingiz tayyor!" (Holat kodi: 200 OK).
      • Sarlavhalar: "Ovqat issiq, ehtiyot boʻling." (javob haqida qoʻshimcha maʼlumot).
      • Tana: Lagʻmonning oʻzi (soʻralgan asosiy maʼlumot).

      3. Xatolik yuz bergan holat

      Agar siz biror ovqatni soʻrasangiz-u, u menyuda boʻlmasa, javob quyidagicha boʻlishi mumkin:

      • Holat qatori: "Afsus, bu ovqat menyuda yoʻq." (Holat kodi: 404 Not Found).
      • Tana: "Bugun faqat somsa bor edi." (qoʻshimcha maʼlumot).

      HTTP ham xuddi shunday ishlaydi, faqat odamlar oʻrniga kompyuterlar bir-biri bilan kod va maʼlumotlar orqali "gaplashadi". Bu jarayon har bir veb-sayt sahifasini ochganingizda, har bir maʼlumotni yuborganingizda millionlab marta sodir boʻladi.

  • Amaliyot

      Node.js yordamida REST API yaratish

      Bu loyiha Node.js-ning o'rnatilgan http va url modullaridan foydalanib, to'liq CRUD (Create, Read, Update, Delete) operatsiyalarini qo'llab-quvvatlaydigan REST API serverini yaratishga qaratilgan. Server uchta alohida modulni (mevalar, mashinalar, foydalanuvchilar) boshqaradi va ma'lumotlarni xotirada (array) saqlaydi.

      Server Talablari

      • Port: 7777
      • Protokol: HTTP
      • Ma'lumot formati: JSON
      • Base URL: http://localhost:7777

      Modullar va Ularning Xususiyatlari

      • Fruits Moduli (/fruits)

        Model maydonlari:

        • id: Unik identifikator (avtomatik yaratiladi)
        • name: Meva nomi (satr, bo'sh bo'lmasligi kerak)
        • price: Narxi (musbat son)
        • count: Soni (musbat son)

      • Cars Moduli (/cars)

        Model maydonlari:

        • id: Unik identifikator (avtomatik yaratiladi)
        • model: Mashina modeli (satr, bo'sh bo'lmasligi kerak)
        • price: Narxi (musbat son)

      • Users Moduli (/users)

        Model maydonlari:

        • id: Unik identifikator (avtomatik yaratiladi)
        • name: Foydalanuvchi ismi (satr, bo'sh bo'lmasligi kerak)
        • age: Yoshi (musbat son)
        • role: Roli (faqat "user", "admin", "seller", "buyer" qiymatlaridan biri)

      HTTP Metodlari va Endpointlar

      GET Operatsiyalari

      • GET /{modul}: Barcha elementlarni olish
      • GET /{modul}/{id}: Ma'lum ID bo'yicha bitta elementni olish

      POST Operatsiyalari

      • POST /{modul}: Yangi element yaratish

      PUT Operatsiyalari

      • PUT /{modul}/{id}: Mavjud elementni yangilash

      DELETE Operatsiyalari

      • DELETE /{modul}/{id}: Elementni o'chirish

      Javob formati va Validatsiya

      Javob formati: Barcha javoblar quyidagi standart JSON formatida bo'lishi kerak:

      {
      "statusCode": 200,
      "message": "success",
      "data": { ... }
    }

      Validatsiya talablari:

      • Fruits uchun: name (satr, bo'sh bo'lmasligi kerak), price (musbat son), count (musbat son)
      • Cars uchun: model (satr, bo'sh bo'lmasligi kerak), price (musbat son)
      • Users uchun: name (satr, bo'sh bo'lmasligi kerak), age (musbat son), role (belgilangan qiymatlardan biri)

      Xatoliklarni Boshqarish (Error Handling)

      • 400: Noto'g'ri ma'lumot formati yoki validatsiya xatolari
      • 404: Element topilmadi
      • 201: Yangi element muvaffaqiyatli yaratildi
      • 200: Operatsiya muvaffaqiyatli bajarildi

      Texnik Talablar

      • Node.js-ning o'rnatilgan http va url modullaridan foydalanish
      • Ma'lumotlarni xotirada (array) saqlash
      • JSON formatida so'rov va javob almashish
      • Har bir modul uchun alohida class yaratish
      • ResData class yordamida javob formatini standartlashtirish

  • Uyga Vazifa

      Shifoxona Boshqaruv Tizimi - Loyiha Talablari

      Bu hujjat Node.js yordamida yaratiladigan shifoxona boshqaruv tizimi uchun REST API loyihasining to'liq shartlarini o'z ichiga oladi. Loyiha bitta server.js faylida amalga oshiriladi va ma'lumotlar array ko'rinishida xotirada saqlanadi. Loyiha turli modullar, API endpointlar, validatsiya qoidalari va fayl tuzilishini qamrab oladi.


      Server Talablari

      • Port: 3000
      • Ma'lumotlar: Xotirada array ko'rinishida saqlanadi.
      • Format: JSON

      Modullar va Ma'lumotlar Modeli

      Quyidagi modullar va ularning maydonlari loyihada ishlatiladi:

      1. Departments (Bo'limlar)
        • id, name, description, head_doctor_id, phone, floor, created_at
      2. Doctors (Shifokorlar)
        • id, first_name, last_name, specialization, phone, email, department_id, license_number, is_head, created_at
      3. Patients (Bemorlar)
        • id, first_name, last_name, birth_date, gender, phone, address, blood_type, created_at
      4. Medical Records (Tibbiy Yozuvlar)
        • id, patient_id, doctor_id, visit_date, diagnosis, treatment, status, created_at
      5. Medicines (Dori-darmonlar)
        • id, name, manufacturer, price, stock_quantity, prescription_required, created_at
      6. Prescriptions (Retseptlar)
        • id, medical_record_id, medicine_id, dosage, frequency, duration, created_at

      API Endpointlari

      Har bir modul uchun asosiy CRUD va qo'shimcha API endpointlari:

      • Departments (/departments)
        • GET /departments - Barcha bo'limlar
        • GET /departments/{id} - Bitta bo'lim
        • POST /departments - Yangi bo'lim
        • PUT /departments/{id} - Bo'limni yangilash
        • DELETE /departments/{id} - Bo'limni o'chirish
        • GET /departments/{id}/doctors - Bo'lim shifokorlari
        • GET /departments/{id}/head-doctor - Bo'lim boshlig'i
      • Doctors (/doctors)
        • GET /doctors - Barcha shifokorlar
        • GET /doctors/{id} - Bitta shifokor
        • POST /doctors - Yangi shifokor
        • PUT /doctors/{id} - Shifokorni yangilash
        • DELETE /doctors/{id} - Shifokorni o'chirish
        • GET /doctors/{id}/patients - Shifokor bemorlari
        • GET /doctors/{id}/medical-records - Shifokor tibbiy yozuvlari
      • Patients (/patients)
        • GET /patients - Barcha bemorlar
        • GET /patients/{id} - Bitta bemor
        • POST /patients - Yangi bemor
        • PUT /patients/{id} - Bemorni yangilash
        • DELETE /patients/{id} - Bemorni o'chirish
        • GET /patients/{id}/medical-records - Bemor tibbiy yozuvlari
        • GET /patients/{id}/prescriptions - Bemor retseptlari
      • Medical Records (/medical-records)
        • GET /medical-records - Barcha tibbiy yozuvlar
        • GET /medical-records/{id} - Bitta yozuv
        • POST /medical-records - Yangi yozuv
        • PUT /medical-records/{id} - Yozuvni yangilash
        • DELETE /medical-records/{id} - Yozuvni o'chirish
        • GET /medical-records/{id}/prescriptions - Yozuv retseptlari
      • Medicines (/medicines)
        • GET /medicines - Barcha dori-darmonlar
        • GET /medicines/{id} - Bitta dori
        • POST /medicines - Yangi dori
        • PUT /medicines/{id} - Dorini yangilash
        • DELETE /medicines/{id} - Dorini o'chirish
        • GET /medicines/low-stock - Kam qolgan dorilar
        • GET /medicines/expired - Muddati o'tgan dorilar
      • Prescriptions (/prescriptions)
        • GET /prescriptions - Barcha retseptlar
        • GET /prescriptions/{id} - Bitta retsept
        • POST /prescriptions - Yangi retsept
        • PUT /prescriptions/{id} - Retseptni yangilash
        • DELETE /prescriptions/{id} - Retseptni o'chirish

      Validatsiya Qoidalari

      Har bir maydon uchun maxsus validatsiya qoidalari qo'llaniladi:

      • Departments
        • name: String, bo'sh bo'lmasligi kerak
        • description: String, ixtiyoriy
        • head_doctor_id: String, mavjud shifokor ID si bo'lishi shart
        • phone: String, telefon formatida bo'lishi shart
        • floor: Number, musbat son bo'lishi shart
      • Doctors
        • first_name, last_name: String, bo'sh bo'lmasligi kerak
        • specialization: String, bo'sh bo'lmasligi kerak
        • email: String, email formatida bo'lishi shart
        • phone: String, telefon formatida bo'lishi shart
        • department_id: String, mavjud bo'lim ID si bo'lishi shart
        • license_number: String, noyob bo'lishi shart
        • is_head: Boolean, mantiqiy qiymat
      • Patients
        • first_name, last_name: String, bo'sh bo'lmasligi kerak
        • birth_date: String, sana formati (YYYY-MM-DD)
        • gender: String, faqat "male" yoki "female"
        • phone: String, telefon formatida bo'lishi shart
        • blood_type: String, qon guruhi formatida bo'lishi shart
      • Medical Records
        • patient_id: String, mavjud bemor ID si bo'lishi shart
        • doctor_id: String, mavjud shifokor ID si bo'lishi shart
        • visit_date: String, sana formati (YYYY-MM-DD)
        • diagnosis: String, bo'sh bo'lmasligi kerak
        • treatment: String, bo'sh bo'lmasligi kerak
        • status: String, faqat "active" yoki "completed"
      • Medicines
        • name: String, bo'sh bo'lmasligi kerak
        • manufacturer: String, bo'sh bo'lmasligi kerak
        • price: Number, musbat son bo'lishi shart
        • stock_quantity: Number, 0 dan katta yoki teng bo'lishi shart
        • prescription_required: Boolean, mantiqiy qiymat
      • Prescriptions
        • medical_record_id: String, mavjud tibbiy yozuv ID si bo'lishi shart
        • medicine_id: String, mavjud dori ID si bo'lishi shart
        • dosage, frequency, duration: String, bo'sh bo'lmasligi kerak

      Bog'liqliklar

      • One-to-One: Department ↔ Head Doctor
      • One-to-Many: Department → Doctors, Patient → Medical Records, Doctor → Medical Records
      • Many-to-Many: Medical Records ↔ Medicines (Prescriptions orqali)
