JavaScript

  • Promise

    1. Promise — bu JavaScript’dagi asinxron operatsiyalarni boshqarish uchun ishlatiladigan obyekt.

      U kelajakda biror natija bo‘lishini (yoki xato) va’da qiladi.

      Promise 3 ta holatga ega:

      1. pending – boshlang‘ich holat (hali bajarilmagan, kutish holatida).

      2. fulfilled – muvaffaqiyatli bajarilgan (resolve chaqirilgan).

      3. rejected – xatolik yuz bergan (reject chaqirilgan).

    2. Oddiy Promise yaratish

                      const myPromise = new Promise((resolve, reject) => {
                let success = true;
            
                setTimeout(() => {
                    if (success) {
                        resolve("✅ Ma'lumot muvaffaqiyatli olindi!");
                    } else {
                        reject("❌ Xatolik yuz berdi!");
                    }
                }, 2000);
            });
            
            // Promise natijasini olish
            myPromise
                .then(result => {
                    console.log(result); 
                })
                .catch(error => {
                    console.error(error); 
                })
                .finally(() => {
                    console.log("⌛ Operatsiya tugadi");
                });

      then → muvaffaqiyatli holat,
      catch → xato holati,
      finally → har ikkala holatda ham ishlaydi.

    3. Promise zanjirlash (chaining)

                  new Promise((resolve) => {
                resolve(2);
            })
            .then(num => {
                console.log(num); // 2
                return num * 2;
            })
            .then(num => {
                console.log(num); // 4
                return num * 2;
            })
            .then(num => {
                console.log(num); // 8
            });

      💡 Har bir then yangi Promise qaytaradi, shu sababli zanjir tuzish mumkin.

  • Promise Methods

      Promise Methodlari.

      1. Promise.then(onFulfilled, onRejected)

        Promise muvaffaqiyatli tugaganda onFulfilled chaqiriladi.

        Birinchi call back (resolve) onFulfilled chiqaradi, agar ikkinchi parametrga ham call back bersak u call back (catch) xato ushlaydi.

                            promise.then(result => {
                      console.log("Natija:", result);
                  });

      2. Promise.catch(onRejected)

        Xatolik yuz berganda ishlaydi.

                          promise.catch(error => {
                  console.log("Xato:", error);
              });

      3. Promise.finally(onFinally)

        Natijadan qat’i nazar, har doim bajariladi.

        Asosan tozalash (cleanup) ishlarida ishlatiladi.

                          promise
                  .then(res => console.log(res))
                  .catch(err => console.log(err))
                  .finally(() => console.log("Tugadi"));

      4. Promise.all(iterable)

        Barcha promise’lar muvaffaqiyatli tugashini kutadi.

        Bittasi xato bo‘lsa, natija catch ga tushadi.

                      Promise.all([
                  Promise.resolve(1),
                  Promise.resolve(2),
                  Promise.resolve(3)
              ]).then(console.log); // [1, 2, 3]
              
              Promise.all([
                  Promise.resolve(1),
                  Promise.reject("Xato"),
                  Promise.resolve(3)
              ]).catch(console.log); // Xato

      5. Promise.allSettled(iterable)

        Barcha promise’lar tugashini kutadi (natija yoki xato bo‘lishidan qat’i nazar).

        Har birining status va value yoki reason qiymatini qaytaradi.

                      Promise.allSettled([
                  Promise.resolve("Ok"),
                  Promise.reject("Xato")
              ]).then(console.log);

      6. Promise.race(iterable)

        Birinchi tugagan promise natijasini qaytaradi (muvaffaqiyat yoki xato bo‘lishi mumkin).

                      Promise.race([
                  new Promise(res => setTimeout(() => res("Tez"), 100)),
                  new Promise(res => setTimeout(() => res("Sekin"), 500))
              ]).then(console.log); // Tez

      7. Promise.any(iterable)

        Birinchi muvaffaqiyatli tugagan promise natijasini qaytaradi.

        Agar hammasi xato bo‘lsa, AggregateError qaytaradi. 

                      Promise.any([
                  Promise.reject("Xato 1"),
                  Promise.reject("Xato 2"),
                  Promise.resolve("Muvaffaqiyatli")
              ]).then(console.log); // Muvaffaqiyatli

    1. Masala: Onlayn kurs platformasi yuklanishi
      Tasavvur qil, sen onlayn ta’lim platformasi yaratding.
      Sahifa yuklanganda 3 ta asosiy ma’lumot serverdan olinishi kerak:

      Kurslar ro‘yxati (getCourses()) — ~3 soniyada keladi.
      O‘qituvchi haqida ma’lumot (getTeacherInfo()) — ~2 soniyada keladi.
      Talaba reytingi (getStudentRank()) — ~4 soniyada keladi.

      Talablar:
      Barcha ma’lumotlar kelgach, ularni bir vaqtda chiqarish kerak (Promise.all).
      Lekin foydalanuvchi kutmasligi uchun, eng tez kelgan ma’lumotni darhol ko‘rsatish (Promise.race).
      Agar ma’lumotlardan bittasi xato bersa, shunga qaramay qolganlarini ko‘rsatish (Promise.allSettled).
      5 soniyadan oshsa, "⏳ Server javob bermadi" deb xabar chiqarish (timeout promise).
      Agar barcha so‘rovlar muvaffaqiyatli bo‘lsa, "✅ Barcha ma’lumotlar yuklandi" degan xabar chiqsin.
      Qo‘shimcha qoidalar:
      API’lar setTimeout bilan simulyatsiya qilinadi.
      Har bir API ba’zan xato (reject) qaytarishi mumkin.
      Kod oxirida barcha usullarning (all, race, allSettled) ishlatilganini ko‘rish kerak.

Agar xonalar mavjud bo'lsa, va'da (Promise) "Buyurtma tasdiqlandi!" kabi xabar bilan amalga oshadi (resolve). Agar mavjud bo'lmasa, va'da rad etiladi (reject) va "Kechirasiz, xonalar mavjud emas." xabarini qaytaradi.

        3. Xatoliklarni boshqarish:
        .then() va .catch() orqali promis natijalarini boshqaring. Agar buyurtma muvaffaqiyatli bo'lsa, tasdiqlash xabarini ko'rsating. Agar muvaffaqiyatsiz bo'lsa, rad etilgan xatoni ushlang va tegishli xabarni chiqaring.

        • getFlightDetails() — "Parvoz ma'lumotlari olingan."

        ● Agar va'dalardan biri muvaffaqiyatsiz bo'lsa (masalan, biron-bir xato yoki rad etilgan holat), .catch() orqali xatoni ushlang va xatolik xabarini chiqaring.
        ● Natija: Agar barcha va'dalar muvaffaqiyatli bajarilsa, konsolda quyidagi ma'lumotlarni ko'rishingiz kerak:
        • "Mehmonxona ma'lumotlari olingan."
        • "Parvoz ma'lumotlari olingan."
        • "Ob-havo ma'lumotlari olingan."
        Agar biror funksiya muvaffaqiyatsiz bo'lsa, bitta umumiy xato xabari chiqadi.

      Promise

      1. Masala: Transactional Checkout (rezerv → to‘lov → yetkazib berish) — atomiklik va rollback
        Oddiy so‘zlarda tushuntirish:
        Bu masalada biz onlayn do‘konda buyurtma qilish jarayonini simulyatsiya qilamiz. Jarayon 3 asosiy bosqichdan iborat:

        • Inventarni rezerv qilish — mahsulotni boshqa odam olib qo‘ymasligi uchun vaqtincha “sizga tegishli” qilib qo‘yish.
        • To‘lovni amalga oshirish — kartadan pulni yechish.
        • Yetkazib berishni rejalashtirish — qaysi kuni va kim olib kelishini belgilash.
        Agar jarayonning istalgan bosqichida xato bo‘lsa, oldingi qadamlar bekor qilinadi:
        ● Rezerv o‘chiriladi (releaseInventory)
        ● Pul qaytariladi (refundPayment)
        Bu atomiklik deyiladi — hammasi birgalikda bo‘lishi yoki umuman bo‘lmasligi.

        Talablar:
        reserveInventory(order)
        ● 2 soniyada bajariladi.
        ● Ba’zan xato beradi.
        ● Agar xato bersa, 2 marta qayta uriniladi (jami 3 urinish).
        ● Har urinish orasida exponential backoff (500ms, 1000ms) bo‘lishi kerak.

        processPayment(paymentInfo)
        ● 2–4 soniyada bajariladi.
        ● Ba’zan xato beradi.
        ● Agar 5 sekunddan oshsa → timeout va xato sifatida qabul qilinadi.

        scheduleDelivery(order)
        ● 1–2 soniyada bajariladi.
        ● Ba’zan xato beradi.
        ● Agar xato bo‘lsa rollback ishlaydi:
        — Agar rezerv muvaffaqiyatli bo‘lsa, releaseInventory chaqiriladi.
        — Agar to‘lov muvaffaqiyatli bo‘lsa, lekin delivery xato qilsa → refundPayment chaqiriladi.

        Natija:
        ● Hammasi muvaffaqiyatli → resolve({status: 'ok', orderId, details})
        ● Xato → reject({status: 'failed', reason})

        Promise usullari ishlatiladi:
        ● Promise.allSettled — parallel bajarilgan ishlarda natijalarni tekshirish uchun.
        ● Promise.race — timeout strategiyasi uchun.

        Edge case’lar (maxsus test holatlari):
        ● Inventar birinchi urinishda xato, ikkinchi urinishda muvaffaqiyatli → jarayon davom etadi.
        ● To‘lov timeout bo‘lsa → rezerv bekor qilinadi, jarayon xato bilan tugaydi.
        ● Delivery xato qilsa → rezerv bekor qilinadi va to‘lov refund qilinadi.
        ● Barcha bosqichlar muvaffaqiyatli bo‘lsa → jarayon ok.

        Kerakli funksiyalar (simulyatsiya uchun):
        ● reserveInventory(order) — mahsulotni rezerv qiladi.
        ● releaseInventory(order) — rezervni bekor qiladi.
        ● processPayment(paymentInfo) — pulni yechadi.
        ● refundPayment(paymentInfo) — pulni qaytaradi.
        ● scheduleDelivery(order) — yetkazib berishni rejalashtiradi.

      2. Masala: Parallel Data Aggregator (bir nechta API so‘rovlarini yig‘ish)
        Oddiy so‘zlarda tushuntirish:
        Sening vazifang — bir vaqtning o‘zida bir nechta mustaqil servisdan ma’lumot olib, ularni bitta javobga yig‘ish. Masalan, sayohat rejalashtirish: mehmonxona, parvoz va ob-havo ma’lumotlarini birga olish. Har bir so‘rov alohida Promise qaytaradi va ular parallel ishlaydi — natijani faqat barcha so‘rovlar tugagach yoki xato yuz berganda qaytarasan.

        Talablar:
        getHotelDetails()
        ● 2 soniya ichida bajarilishi kerak.
        ● Muvaffaqiyatli bo‘lsa: "Mehmonxona ma'lumotlari olingan."
        ● Ba’zan reject bo‘lishi mumkin.

        getFlightDetails()
        ● 2–3 soniya ichida bajariladi.
        ● Muvaffaqiyatli bo‘lsa: "Parvoz ma'lumotlari olingan."
        ● Ba’zan reject bo‘lishi mumkin.

        getWeatherDetails()
        ● 1–2 soniya ichida bajariladi.
        ● Muvaffaqiyatli bo‘lsa: "Ob-havo ma'lumotlari olingan."
        ● Ba’zan reject bo‘lishi mumkin.

        bookTrip() funksiyasi:
        ● Ushbu uchta funksiyani parallel ishga tushiradi.
        ● Asosiy mexanizm: Promise.all() (ya’ni hammasi muvaffaqiyatli bo‘lishi kerak).
        ● Agar hammasi muvaffaqiyatli bo‘lsa → resolve bilan barcha natijalarni qaytaradi.
        ● Agar bittasi ham reject qilsa → umumiy xato (reject) qaytaradi.
        ● Har bir so‘rov uchun 5 soniya umumiy timeout (agar umumiy yoki individual so‘rov 5s dan oshsa — xato).

        Qo‘shimcha talab:
        ● Promise.allSettled dan foydalanish imkoniyati (masalan, diagnostika yoki loglash uchun), ammo yakuniy biznes-natija Promise.all mantig‘iga bog‘liq.

        Edge case’lar:
        ● Hammasi muvaffaqiyatli: uchta xabar qaytadi va bookTrip() yakunida ko‘rsatiladi.
        ● Bittasi reject: masalan, getFlightDetails() xato qilsa → umumiy xato.
        ● Biror so‘rov juda sekin: agar 5s dan oshsa → timeout va xato.
        ● Bir nechta reject: bir vaqtning o‘zida xatolar bo‘lsa → umumiy xato (qaysi servislar xato qilgani logda ko‘rinishi mumkin).
        ● Service intermittent: ba’zi servislar vaqti-vaqti bilan reject bo‘lsa, test holatida ham ko‘rib chiqiladi.

        Kerakli funksiyalar (simulyatsiya uchun):
        ● getHotelDetails() — Promise, 2s, success yoki reject.
        ● getFlightDetails() — Promise, 2–3s, success yoki reject.
        ● getWeatherDetails() — Promise, 1–2s, success yoki reject.
        ● bookTrip() — boshqaruvchi funksiya; unda Promise.all, timeout va xato boshqaruvi amalga oshiriladi.
        ● (Ixtiyoriy) withTimeout(promise, ms) — berilgan promise uchun timeout mexanizmi.
        ● (Ixtiyoriy) logResults(results) — allSettled natijalarini diagnostika uchun qayd etish.

      3. Masala: Batch Job Processor (navbat bilan va parallel bajarish)
        Oddiy so‘zlarda tushuntirish:
        Senga bir qator «vazifalar» (jobs) beriladi. Ularni guruhlarga (batch) bo‘lib bajarish kerak: Har bir batch ichida bir nechta job parallel ishlaydi (batchSize ga muvofiq), keyingi batch esa faqat oldingi to‘liq tugagandan so‘ng boshlanadi. Har bir job Promise qaytaradi va ba’zan xato bo‘lishi mumkin. Yakunda har bir job uchun muvaffaqiyat yoki muvaffaqiyatsizlik qaytariladi.

        Talablar:
        simulateJob(name)
        ● Ishlash vaqti: 1–3 soniya tasodifiy.
        ● Ba’zan reject bo‘lishi mumkin (tasodifiy xatolik).

        runJobsInBatches(jobs, batchSize)
        ● jobs — job funksiyalari ro‘yxati (Promise qaytaruvchi).
        ● batchSize — har bir batch ichida parallel bajariladigan joblar soni.
        ● Ishlash tartibi:
          1. Birinchi batch: jobs[0..batchSize-1] parallel bajariladi.
          2. Keyingi batch: jobs[batchSize..2*batchSize-1] — faqat oldingi batch tugagach boshlanadi.
          3. Oxirigacha shu tartibda.
        ● Har batch ichida Promise.allSettled() ishlatiladi, shunda xato bo‘lsa ham batch oxirigacha yetadi.
        ● Yakuniy natija: barcha job’lar uchun { name, status: 'fulfilled'|'rejected', value|reason } kabi obyektlar ro‘yxati.
        ● Agar butun protsessni bekor qilish kerak bo‘lsa (masalan, critical error), reject mexanizmi bo‘lishi kerak.

        Edge case’lar:
        ● Barcha job’lar muvaffaqiyatli → hammasi fulfilled bo‘ladi.
        ● Ba’zilari xato → allSettled natijalarida muvaffaqiyat va xato ro‘yxati qaytariladi.
        ● batchSize = 1 → job’lar ketma-ket bajariladi.
        ● batchSize >= jobs.length → barcha job’lar bir martada parallel bajariladi.
        ● jobs bo‘sh → bo‘sh natija qaytariladi.
        ● Bir job juda uzoq davom etsa → ixtiyoriy timeout bilan boshqarish mumkin.

        Kerakli funksiyalar (simulyatsiya uchun):
        ● simulateJob(name) — 1–3s ichida resolve(name + ' done') yoki reject(error) qaytaradi.
        ● runJobsInBatches(jobs, batchSize) — batch boshqaruvi va natijalarni yig‘ish.
        ● (Ixtiyoriy) collectResults(allSettledResults) — yakuniy formatlash.
        ● (Ixtiyoriy) withTimeout(promise, ms) — har job yoki batch uchun timeout.
