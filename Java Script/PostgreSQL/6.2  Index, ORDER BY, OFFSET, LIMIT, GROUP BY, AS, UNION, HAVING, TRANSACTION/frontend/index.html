Oson LIMIT & OFFSET
#1

📄 Pagination (Sahifalash) Tizimi

Masala sharti:

main.users jadvalidan foydalanuvchilarni sahifalab olish kerak. Har bir sahifada 3 ta foydalanuvchi ko'rsatiladi. 2-sahifadagi foydalanuvchilarni oling (ya'ni 4, 5, 6-foydalanuvchilar).

💡 Maslahat: offset = (page - 1) * count formulasidan foydalaning 

-- 2-sahifa, har sahifada 3 ta yozuv
-- offset = (2 - 1) * 3 = 3

SELECT * FROM main.users 
LIMIT 3 
OFFSET 3;

✅ Natija: 4, 5, 6-foydalanuvchilar qaytariladi (id bo'yicha)

Oson ORDER BY
#2

🔄 Saralash (Sorting)

Masala sharti:

main.users jadvalidan barcha foydalanuvchilarni oling. Natijalarni avval balance bo'yicha kamayish tartibida, keyin age bo'yicha o'sish tartibida saralashtiring.

💡 Maslahat: Bir nechta ustun bo'yicha saralashda vergul bilan ajrating 

-- Balance bo'yicha kamayish (DESC), Age bo'yicha o'sish (ASC)

SELECT * FROM main.users 
ORDER BY balance DESC, age ASC;

✅ Natija: Eng katta balansli foydalanuvchilar birinchi, teng balansda yoshroqlari oldin

O'rta GROUP BY & HAVING
#3

📊 Guruhlash va Filtrlash

Masala sharti:

main.users jadvalidan foydalanuvchilarni role bo'yicha guruhlang. Har bir rolda nechta foydalanuvchi borligini hisoblang. Faqat 2 va undan ko'p foydalanuvchisi bor rollarni ko'rsating.

💡 Maslahat: HAVING - GROUP BY dan keyingi shartlar uchun ishlatiladi 

-- Role bo'yicha guruhlash, 2+ foydalanuvchili rollar

SELECT 
    role,
    COUNT(*) AS user_count
FROM main.users 
GROUP BY role 
HAVING COUNT(*) >= 2
ORDER BY user_count DESC;

✅ Natija: 'client' - 3 ta, 'manager' - 2 ta kabi natijalar

O'rta ALTER TABLE
#4

🔧 Jadval Strukturasini O'zgartirish

Masala sharti:

main.users jadvaliga quyidagi o'zgartirishlarni kiriting:

  1. phone ustunini qo'shing (VARCHAR(20), default NULL)
  2. is_active ustunini qo'shing (BOOLEAN, default TRUE)
  3. nickname ustunini o'chiring (agar mavjud bo'lsa)

💡 Maslahat: ADD COLUMN va DROP COLUMN buyruqlaridan foydalaning 

-- 1. Phone ustunini qo'shish
ALTER TABLE main.users 
ADD COLUMN phone VARCHAR(20) DEFAULT NULL;

-- 2. is_active ustunini qo'shish
ALTER TABLE main.users 
ADD COLUMN is_active BOOLEAN DEFAULT TRUE;

-- 3. nickname ustunini o'chirish
ALTER TABLE main.users 
DROP COLUMN IF EXISTS nickname;

-- Natijani tekshirish
SELECT * FROM main.users LIMIT 3;

✅ Natija: Jadvalda phone va is_active ustunlari paydo bo'ladi, nickname o'chiriladi

O'rta INDEX
#5

⚡ Indekslar bilan Optimizatsiya

Masala sharti:

main.users jadvalida qidiruv tezligini oshirish uchun indekslar yarating:

  1. email ustuniga B-Tree indeks (tez-tez qidiriladi)
  2. full_name ustuniga Hash indeks (aniq moslik qidiruvi uchun)
  3. role va is_active ustunlariga kompozit indeks

💡 Maslahat: B-Tree - tartiblangan qidiruv, Hash - aniq moslik uchun 

-- 1. Email uchun B-Tree indeks (default)
CREATE INDEX idx_users_email 
ON main.users (email);

-- 2. Full_name uchun Hash indeks
CREATE INDEX idx_users_fullname 
ON main.users USING hash (full_name);

-- 3. Kompozit indeks (role + is_active)
CREATE INDEX idx_users_role_active 
ON main.users (role, is_active);

-- Indekslarni ko'rish
SELECT indexname, indexdef 
FROM pg_indexes 
WHERE tablename = 'users';

✅ Natija: So'rovlar tezligi sezilarli darajada oshadi, ayniqsa katta ma'lumotlarda

Qiyin TRANSACTION
#6

🔒 Tranzaksiya - Pul O'tkazish

Masala sharti:

Foydalanuvchilar orasida xavfsiz pul o'tkazish amalga oshiring. id=1 foydalanuvchidan id=2 foydalanuvchiga 200 so'm o'tkazilsin. Agar biror xatolik bo'lsa, barcha o'zgarishlar bekor qilinsin.

⚠️ Muhim: Jo'natuvchida yetarli mablag' borligini tekshiring! 

-- Tranzaksiya bilan xavfsiz pul o'tkazish
BEGIN;

-- Jo'natuvchidan pul ayirish
UPDATE main.users 
SET balance = balance - 200 
WHERE id = 1 AND balance >= 200;

-- Qabul qiluvchiga pul qo'shish
UPDATE main.users 
SET balance = balance + 200 
WHERE id = 2;

-- Hammasi to'g'ri bo'lsa tasdiqlash
COMMIT;

-- Xatolik bo'lsa bekor qilish
-- ROLLBACK;

-- Natijani tekshirish
SELECT id, full_name, balance 
FROM main.users 
WHERE id IN (1, 2);

✅ Natija: id=1 ning balansi 200 ga kamayadi, id=2 ning balansi 200 ga oshadi yoki hech narsa o'zgarmaydi

Qiyin JOIN
#7

🔗 Jadvallarni Birlashtirish (JOIN)

Masala sharti:

main.messages jadvalidagi barcha xabarlarni oling. Har bir xabar uchun jo'natuvchi va qabul qiluvchining to'liq ismlarini ko'rsating. Faqat o'qilmagan (is_read = FALSE) xabarlarni filtrlang.

💡 Maslahat: Bir jadvalga ikki marta JOIN qilish uchun alias ishlatiladi 

-- O'qilmagan xabarlar bilan jo'natuvchi va qabul qiluvchi ismlari

SELECT 
    m.id AS message_id,
    m.message,
    sender_user.full_name AS sender_name,
    receiver_user.full_name AS receiver_name,
    m.is_read
FROM main.messages m
INNER JOIN main.users sender_user 
    ON m.sender = sender_user.id
INNER JOIN main.users receiver_user 
    ON m.receiver = receiver_user.id
WHERE m.is_read = FALSE
ORDER BY m.id;

✅ Natija: Har bir o'qilmagan xabar, jo'natuvchi va qabul qiluvchi ismlari bilan ko'rsatiladi
